# Part III: Evidence & validation — introduction

Part III documents what the substrate does, measured against named
reference sources. Behaviour is defined by a tiered spec suite before
code is written; every claim here is backed by a test or a cited
measurement, not by assertion.

## Validation philosophy

Stratum's validation is bounded by five reference sources:

- **RFC test vectors** — RFC 2697/2698/2859 conformance vectors for the
  srTCM, trTCM, and TSW meters (Appendix A carries the full tables).
- **The 2001 ns-2.35 cross-port** — the same 2001 DiffServ4NS module
  ported to ns-2.35 and run as a second simulator; differences expose
  port divergences, not scenario uncertainty.
- **Chang et al. 2015 reproduction** — an independent three-scenario
  reproduction that provides a second reference trajectory for the
  DiffServ client.
- **The CAKE paper reproduction** — Hoeiland-Joergensen et al. 2018,
  validated at matched operating points including the Linux-netns
  cross-validation backend.
- **Inherited TF-TANT measurements** — the original 2001 validation
  measurements carried forward as regression anchors.

Every fidelity boundary — what was not reproduced, what was deferred,
what depends on a platform-specific parameter — is stated plainly in the
chapter that documents it.
